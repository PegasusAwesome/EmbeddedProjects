# Todoes Agent Notes

This is an Arduino/LVGL project for a Waveshare ESP32-S3 RGB touch screen, 1024x600 pixels, with GT911 touch.

Important files:
- `Todoes.ino` initializes the touch controller, RGB panel, LVGL port, and starts `todo_ui_init()`.
- `lvgl_port.*`, `rgb_lcd_port.*`, `gt911.*`, `touch.*`, `i2c.*`, and `io_extension.*` are hardware/platform support. Avoid changing these unless the task is specifically about display or touch bring-up.
- `ui/` is generated by SquareLine Studio. Do not put durable app logic there because it can be regenerated.
- `todo_model.*` is the canonical todo data model. It supports parent/sub-todo relationships, `done`, `expanded`, and `display`.
- `todo_storage.*` persists the model using ESP32 `Preferences`. It stores compact per-item records plus metadata; avoid returning to a single fixed blob for all 80 possible items.
- `todo_ui.*` builds the current LVGL app UI dynamically.

Build command:

```powershell
arduino-cli compile --fqbn esp32:esp32:waveshare_esp32_s3_touch_lcd_7 --build-path C:\Users\Marcel\idfworkspace\Todoes\.build .
```

The `.build/` directory is generated output and is ignored.

Design direction:
- Treat the second screen as a future synchronized view of the same todo model.
- Keep `TodoItem.display` as the routing field: `TODO_DISPLAY_ACTIVE` for the todo screen, `TODO_DISPLAY_DONE` for the later done screen.
- The current UI renders only active-display root items and their visible children.
- The `done` field remains in the model for future swipe-to-done behavior, but the UI currently has no checkbox.
- A future swipe action should call `todo_model_move_to_display(id, TODO_DISPLAY_DONE, true)` and then persist/refresh.

Constraints:
- Prefer fixed-size data structures over heap-heavy dynamic containers on the ESP32 UI path.
- Keep app code outside generated SquareLine files.
- Use `lvgl_port_lock()` before calling LVGL APIs from code that is not already running inside LVGL event handling.
